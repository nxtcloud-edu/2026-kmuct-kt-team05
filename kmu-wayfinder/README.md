# 북악 내비 — 국민대 캠퍼스 길찾기

> 강의실에서 강의실까지, **계단을 최소화하는** 실내외 통합 경로 안내

국민대 북악캠퍼스는 경사면에 지어져서 평면 최단거리가 실제로는 최악의 경로인 경우가 많습니다.
일반 지도앱은 경사도, 계단 수, 건물 간 실내 연결통로를 모르기 때문에 이 문제를 풀 수 없습니다.
이 프로젝트는 그 세 가지를 데이터로 갖고 경로를 계산합니다.

## 실행

빌드 단계가 없습니다. Node도 npm도 필요 없습니다.

```
index.html 을 브라우저로 열면 끝입니다.
```

로컬 서버로 띄우고 싶으면:

```powershell
py -m http.server 8000
# http://localhost:8000 접속
```

## 배경 지도

`assets/campusmap.png` 가 이미 들어가 있고, 좌표계는 그 이미지 크기인 **824 x 611** 입니다.
건물 좌표는 지도에 찍힌 핀의 뾰족한 끝을 자동 검출해서 맞춰놨으므로 정렬이 정확합니다.
파일을 지우면 추상 베이스맵으로 자동 대체되며, 그래도 길찾기는 정상 동작합니다.

> **라이선스 주의** 현재 배경은 포털 지도 서비스의 화면 캡처입니다.
> 내부 데모까지는 괜찮지만, 제출물이나 공개 배포에 그대로 쓰면 저작권 문제가 될 수 있습니다.
> 발표용으로는 배경을 빼거나(추상 베이스맵으로 자동 대체됨), 학교 제공 캠퍼스맵 또는
> 직접 그린 도면으로 바꾸는 쪽이 안전합니다.

지도를 다른 이미지로 바꿀 때는 이 순서로 하면 됩니다.

```powershell
# 1. 새 이미지를 assets/campusmap.png 로 저장 (클립보드에 있으면 아래 스크립트로)
powershell -STA -ExecutionPolicy Bypass -File tools\grab_clipboard.ps1

# 2. 크기 확인
py tools\imgsize.py assets\campusmap.png

# 3. js/render.js 의 VIEW_W / VIEW_H 와 css/styles.css 의 aspect-ratio 를 새 크기로 수정

# 4. 기존 좌표를 새 크기에 맞게 일괄 변환
py tools\rescale_coords.py <이전W> <이전H> <새W> <새H>

# 5. 지도에 핀이 찍혀 있으면 자동 검출로 정밀 보정
py tools\detect_pins.py        # tools/_pins_debug.png 로 눈으로 확인
py tools\shot.py map           # 정렬 결과 확인
```

## 네 가지 이동 모드

같은 출발·도착인데 모드에 따라 **비용의 정의가 달라져서** 전혀 다른 경로가 나옵니다.
이게 이 서비스의 핵심이고, 데모의 하이라이트입니다.

| 모드 | 무엇을 최적화하나 | 정문 → 북악관 실측 |
|---|---|---|
| ⚡ 최단시간 | 거리 위주, 계단 감수 | 7분 / 433m / **계단 123칸** / 실내 0% |
| 🦵 계단 최소 | 계단을 피해서 돌아감 | 8분 / 460m / **계단 0칸** / 실내 20% |
| ♿ 무장애 | 계단 구간을 통행 불가로 처리 | 8분 / 460m / 계단 0칸 / 실내 20% |
| 🌧️ 비 안 맞기 | 실내·지붕 구간 우선 | 7분 / 429m / 계단 18칸 / **실내 31%** |

**계단 123칸을 0칸으로 줄이는 값이 1분입니다.** 이 한 줄이 발표의 핵심입니다.

비용 함수는 `js/graph.js` 의 `edgeCost()` 한 곳에 모여 있습니다.

```
cost = 거리(m)
     + 계단패널티 × 오르는계단
     + 계단패널티 × 0.4 × 내려가는계단    ← 내려가는 건 덜 힘드니까
     + 경사패널티 × 오르는높이
     + 실외패널티 × 실외거리              ← 비 오는 날만
     + 엘리베이터 대기시간 × 보행속도     ← 기다리는 시간을 거리로 환산
```

모든 항을 **미터 단위로 통일**한 게 중요합니다. 그래야 "엘리베이터 35초 기다리기"와
"계단 20칸 오르기"를 같은 자로 비교할 수 있습니다.

축척은 `SCALE_M_PER_PX = 0.85` 입니다. 공학관~과학관 610px 을 약 500m 로 보고 잡은 값이니,
실제 거리를 아는 두 지점으로 다시 계산하면 정확도가 올라갑니다.

## ⚠️ 지금 당장 고쳐야 할 데이터

**코드는 완성됐고, 남은 건 데이터 정확도입니다.** 여기가 프로젝트의 진짜 자산입니다.

### 1. 건물 고도 (`js/data.js` 의 `elev`)

현재 값은 전부 **추정치**입니다. 정문을 0m로 두고 상대 고도를 적어둔 것인데,
이 값에서 계단 수와 경사 패널티가 자동 계산되므로 서비스 품질이 여기서 갈립니다.

재학생 체감으로 "정문 대비 몇 층 높이인지"만 잡아도 충분히 좋아집니다.
한 층을 약 4m로 보면 됩니다.

### 2. 건물 간 실내 연결통로 (`type: 'bridge'` / `'indoor'`)

**이게 일반 지도앱이 절대 못 가진 데이터입니다.** 인터넷에 없고, 재학생 기억에만 있습니다.
현재 확인되지 않은 추정 연결이 11건 있고, 앱 상단 **데이터 점검** 버튼을 누르면 전부 나열됩니다.

확인해야 할 것:

- 어떤 건물끼리 실내로 연결돼 있나? **몇 층에서** 연결되나?
- 엘리베이터가 실제로 있는 건물은? (`elevator: true/false`)
- 휠체어로 통행 가능한 경사로가 실제로 있는 구간은?

연결통로를 하나 추가하는 방법:

```js
// js/data.js 의 EDGES 배열에 한 줄 추가
['bukak', 'johyung', 'bridge', { note: '북악관 4층 ↔ 조형관 2층 연결통로' }],
```

`needsVerify: true` 를 지우면 경고 목록에서 사라집니다.

### 3. 접근성 취약 구간

현재 **박물관**은 무장애 경로가 존재하지 않습니다. 이건 버그가 아니고
데이터상 계단 외 접근 수단이 없다는 뜻입니다. 실제로 그런지 확인해보세요.
사실이면 발표에서 쓸 수 있는 발견입니다.

## AI는 어디에 쓰이나

경로 탐색 자체는 다익스트라이고 AI가 아닙니다. AI는 세 군데에 들어갑니다.

1. **자연어 입력 해석** — "미래관에서 북악관 411호 가는데 계단 싫어" → 출발/도착/모드 추출
2. **경로 내레이션** — 그래프 경로를 사람이 읽을 문장으로 변환
3. (확장) 시간표 이미지 업로드 → OCR → 다음 수업 강의실 자동 인식

중요한 설계 결정: **1번과 2번은 규칙 기반 파서로도 완전히 동작합니다.**
AI는 그 위에 얹는 보강 레이어입니다. 발표 중 API가 죽어도 데모가 깨지지 않습니다.

### API 키 설정

앱 하단 **AI 설정**에서 키를 넣으면 켜집니다. 키는 `localStorage` 에만 저장되고
코드에는 들어가지 않습니다.

> **보안 경고** 브라우저에서 API를 직접 호출하므로 키가 클라이언트에 노출됩니다.
> 해커톤 데모용으로만 쓰세요. 실제 서비스로 만들 거라면 서버(또는 서버리스 함수)를
> 두고 키를 거기 보관해야 합니다.

## 발표 시나리오

즉흥으로 하지 말고 이 세 개만 반복 연습하세요. 특히 2번이 핵심입니다.

**1. 강의실 코드로 바로 찾기**
입력: `미래관에서 북악관 411호`
→ 건물 앞이 아니라 4층 411호까지 안내하는 것을 보여줍니다.

**2. 같은 경로, 모드만 바꾸기** ← 제일 중요
`정문 → 북악관` 을 최단시간으로 띄운 뒤 무장애로 전환합니다.
계단 **123칸 → 0칸**, 추가 비용은 **1분**. 지도 위 경로 색까지 바뀝니다
(빨강 점선 = 계단, 초록 = 경사로, 자홍 = 엘리베이터).
"구글맵은 이걸 못 합니다"를 여기서 말하세요.

**3. 자연어 + 접근성 발견**
입력: `정문에서 성곡도서관 휠체어로 갈 수 있어?`
→ 휠체어라는 단어만으로 무장애 모드가 잡히는 것을 보여줍니다.
이어서 박물관으로 바꾸면 "무장애 경로 없음"이 나옵니다.
→ "우리 서비스는 길을 찾아주기도 하고, 캠퍼스의 접근성 공백을 찾아내기도 합니다."

```
kmu-wayfinder/
├── index.html          UI 골격
├── css/styles.css      스타일 (외부 폰트/프레임워크 없음)
├── js/
│   ├── data.js         ★ 캠퍼스 데이터. 여기만 고치면 됩니다
│   ├── graph.js        경로 엔진 (양방향 그래프 + 모드별 다익스트라)
│   ├── parse.js        자연어 파싱 + 내레이션 + LLM 래퍼
│   ├── render.js       SVG 지도 렌더링
│   └── app.js          UI 조립
├── assets/
│   └── campusmap.png   배경 지도 (824x611)
└── tools/              개발용 도구 — 제출물에서 빼도 무관
    ├── selftest.html   로직 회귀 테스트 39개
    ├── runtest.py      위 테스트를 Edge 헤드리스로 실행
    ├── shot.py         화면을 PNG 로 저장 (정렬 확인용)
    ├── detect_pins.py  배경 지도의 핀 위치 자동 검출
    ├── apply_coords.py 검출한 좌표를 data.js 에 반영
    ├── rescale_coords.py  좌표계 크기 변경 시 일괄 변환
    ├── imgsize.py      이미지 크기 확인
    └── grab_clipboard.ps1  클립보드 이미지를 배경 지도로 저장
```

## 테스트

`js/data.js` 를 고친 뒤 무언가 깨졌는지 확인하려면:

- **간단히**: 앱 상단 **데이터 점검** 버튼. 끊긴 보행로, 고립된 건물, 미확인 연결을 즉시 알려줍니다.
- **전체 회귀**: `tools/selftest.html` 을 브라우저로 엽니다. 39개 검사가 돌아갑니다.
- **자동화**: `py tools/runtest.py` (Edge 헤드리스 사용, 결과는 `tools/_result.txt`)

## 남은 확장 아이디어

시간이 남으면 이 순서로 붙이는 걸 권합니다. 위쪽이 투자 대비 효과가 큽니다.

1. **시간표 이미지 업로드** → 비전 모델로 강의실 코드 추출 → 다음 수업까지 경로.
   "지금 나가세요" 기능은 이미 `leaveAdvice()` 로 구현돼 있어서 입력만 연결하면 됩니다.
2. **경로 공유 URL** — 쿼리스트링에 출발/도착/모드를 담아 링크로 공유.
3. **크라우드소싱** — 학생이 "여기 계단 있어요" 를 제보하는 폼. 발표에서 확장성 근거가 됩니다.
4. **셔틀버스 / 정릉역·길음역 연계** — 캠퍼스 밖 노드를 추가하면 그대로 동작합니다.

## 알려진 한계

- 건물 좌표는 배경 지도 픽셀 좌표입니다. GPS 좌표가 아니라서 실시간 위치 추적은 안 됩니다.
  (핀 검출로 지도와의 정렬 자체는 정확합니다)
- 고도값은 추정치입니다. (위 "지금 당장 고쳐야 할 데이터" 참고)
- 축척 0.85 m/px 도 어림값입니다. 실제 거리를 아는 두 지점으로 재계산하세요.
- 배경 지도는 포털 캡처라 공개 배포 시 라이선스 문제가 있습니다.
- 실내 층별 도면은 아직 없습니다. 건물 내부는 "몇 층"까지만 안내합니다.
- 접근성은 자동 검사로 완전히 보장할 수 없습니다. 실제 휠체어 이용자 검증과
  보조기술 테스트가 필요합니다.
