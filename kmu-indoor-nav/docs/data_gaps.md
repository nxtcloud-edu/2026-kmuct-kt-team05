# 현장 확인 필요 항목 (data gaps)

작성: 2026-09-20 · 대상 그래프: `mirae-indoor-v1` · 정책: `policy-2026.09.20-01`

이 문서는 **대상 ID 별**로 무엇을 확인해야 하고, 그것이 **어떤 요청을 막고 있는지**,
그리고 **우회 구현이 가능한지**를 적는다.

측정 원칙
- 스마트폰 측정·도면 판독을 전문 실측과 같게 취급하지 않는다.
  `Observation.method` 에 측정 수단을 그대로 적는다.
- 미확인 값을 `0` 이나 `이용 가능` 으로 채우지 않는다.
- 접근성 판정에 쓰려면 `verification = field_measured` 가 필요하다
  (`schema.MIN_VERIFICATION_FOR_ACCESSIBILITY`).
- 결과는 `data/survey/observations.csv` 에 1행 1관측으로 기록한다.

## C. 338호 / 337호 접근성 속성

### C-1. 문 4개소

| 대상 ID | 도면 위치 (px) | 현재 값 |
|---|---|---|
| `mirae/F3/e/door/338-W` | 개구부 x 913.8–923.8, y 331.5 | 폭 1.01 m (`drawing_read`), 문턱·개폐 `unknown` |
| `mirae/F3/e/door/338-E` | 개구부 x 1009.5–1020.0, y 331.5 | 폭 1.06 m (`drawing_read`), 문턱·개폐 `unknown` |
| `mirae/F3/e/door/337-W` | 개구부 x 1086.3–1096.3, y 331.5 | 폭 1.01 m (`drawing_read`), 문턱·개폐 `unknown` |
| `mirae/F3/e/door/337-E` | 개구부 x 1180.0–1190.0, y 331.5 | 폭 1.01 m (`drawing_read`), 문턱·개폐 `unknown` |

지도상 위치: 미래관 3층 북측 실열, 복도에서 338호·337호로 들어가는 문.
338호는 서·동 2개소, 337호도 서·동 2개소.

확인할 것
1. **유효폭** — 문짝을 90° 연 상태에서 문틀 안목 치수. 도면 개구부 폭과 다르다.
2. **문턱 높이** — 단차 mm 단위. 0 이면 0 으로 기록(근거와 함께).
3. **개폐 방식** — 수동/자동, 여닫이/미닫이, 개폐력, 손잡이 형태(레버/노브).
4. **폐쇄 여부** — 평소 잠겨 있는 문이 있는가.

막고 있는 요청: 「휠체어로 338호」. 현재 이 4개 엣지가 `required_accessibility_unverified`
로 제거되어 `insufficient_verified_data` 가 된다.

우회 구현: 조사용 후보 경로는 별도 응답으로 제공 가능(미확인 구간 강조).
접근성 확인 경로로는 제공 불가.

### D-2. 정문 → 미래관 접근로

| 항목 | 내용 |
|---|---|
| 현재 상태 | **연결 불가.** 기존 실외 시제품(`data/graph.json`)은 건물 중심점→최근접 보행노드 **가상 연결**을 쓰며, 사용자용 그래프에 포함하지 않았다 |

| 우회 구현 | **확인된 미래관 외부 지점부터** 부분 완성. 정문 연결은 보류 |

## 조사 우선순위

1. **B-2 승강기** — 배리어프리 층간 경로의 유일한 수단. 없으면 프로젝트 핵심 주장이 성립하지 않는다.
2. **B-1 계단 출입문** — 층간 경로의 최소 성립 조건.
3. **C-1 문 4개소** — 같은 층 휠체어 경로를 `ok` 로 바꾸는 최소 항목. 측정 대상이 4곳뿐이라 비용이 가장 낮다.
4. **B-3 층 확정** — 안내문·층 순서 정확성.
5. **C-2 복도 유효폭** — 5구간.
6. **D-1 외부 출입구** — 실외 통합의 시작점.
7. **F 축척·정합**, **E 시간 모델** — 정확도 향상.

3번(문 4개소)만 실측하면 `338↔337 휠체어 경로`가 `insufficient_verified_data` →
`ok` 로 바뀌는지 바로 확인할 수 있다. 가장 작은 단위의 검증 사이클이다.
